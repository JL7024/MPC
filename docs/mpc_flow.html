MPC 项目数据流流程图

每个块用中文作用做标题，函数名放在块内；箭头标签表示实际传递的变量。

1. 场景生成到闭环仿真

对应 main.py::run_case() 到 main.py::run_simulation()。虚线框内部是每一拍循环。

2. MPC 单拍求解内部

对应 controllers/mpc.py::solve()。这里展示一次 solve() 内部怎样更新参数并调用 OSQP。

MPC 线性化约束： x_{k+1} ≈ A_k x_k + B_k u_k + c_k 参考控制： delta_ref = atan(L * kappa_ref) a_ref = 0 滚动时域： 每拍求 u_0 ... u_{N-1}，只执行 u_0

3. A* 场景的参考轨迹生成

只有 A* 场景先做全局搜索。普通直线、圆、双移线等场景直接生成参考轨迹。

函数名解释

函数 / 变量 作用
scene_fn() 场景工厂函数。返回一个 Scenario，包含参考轨迹、初始状态和可选障碍物。
ReferenceTrajectory 参考轨迹对象。核心数据是 ref.points，每行是 [x, y, phi, v, kappa, s]。
find_nearest() 根据当前车辆位置 x,y，在参考轨迹上找最近点索引 nearest_idx。
get_reference_window_by_time() 从 nearest_idx 开始，按未来时间 dt 取 N+1 个参考状态。
linearize() 把非线性自行车模型在参考点附近一阶线性化，得到 A_k, B_k, c_k。
prob.solve(OSQP) 调用 OSQP 求解当前拍的二次规划 QP，输出未来控制序列。
car.step() 用当前控制 u_opt 推进车辆真值状态。
hist 仿真历史记录，包括真值状态、控制量、参考索引、求解时间、预测轨迹等。
